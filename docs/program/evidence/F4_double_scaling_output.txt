  Scaler STATISTICS are contaminated, but the fold-training VALUES
  are bit-identical. Robust/standard scaling is AFFINE, and the
  fold scaler re-derives its statistics from the pre-scaled
  fold-train data, so the first transform cancels exactly:

      pre  : z = (x - m)/s                     [global m, s]
      fold : w = (z - med(z_tr)) / IQR(z_tr)
           =  (x - med(x_tr)) / IQR(x_tr)      [m, s cancel]

RESULT: NO LEAKAGE -- claim REFUTED

  Phase 0 (Agent 4) reported 'global scaler fit precedes CV folds'
  as HIGH-severity leakage. That is REFUTED for the CV/OOF path.
  What remains is redundant computation, not a correctness defect.

  THE INVARIANT THIS RELIES ON: every reachable scaler is affine.
  AdapterScaler accepts only robust/standard/minmax and raises
  otherwise; FoldAwareScaler accepts only none/robust/standard.
  ScalerType also declares QUANTILE, which is NOT affine -- if it
  ever becomes reachable as the pre-scaler, the cancellation breaks
  and this DOES become real leakage. That invariant is now pinned by
  tests/test_scaling_invariants.py rather than left implicit.
